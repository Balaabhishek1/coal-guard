# DATABASE_SCHEMA.md

## 1. Database Overview & Extensions

The platform uses **PostgreSQL 16** as the primary datastore, heavily augmented by two specialized extensions to handle the unique demands of mining governance:
* **PostGIS 3.4:** Enables spatial columns (`GEOMETRY`) to store mine lease boundaries, active benches, and underground gallery coordinates.
* **TimescaleDB:** Converts standard PostgreSQL tables into time-partitioned "hypertables" to handle millions of high-frequency gas and hardware telemetry rows without degrading relational query performance.

```sql
-- Required PostgreSQL Extensions
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS timescaledb;
CREATE EXTENSION IF NOT EXISTS pgcrypto; -- For native SHA-256 hashing if needed
```

## 2. Core Identity & Workforce Module

### 2.1. `users` (RBAC & Identities)
Stores all personnel, from corporate administrators and DGMS auditors down to underground shift miners.

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    rfid_tag VARCHAR(128) UNIQUE,             -- Scanned at pithead turnstile / cap-lamp rack
    full_name VARCHAR(255) NOT NULL,
    role VARCHAR(50) NOT NULL,                -- e.g., 'MINER', 'OVERMAN', 'MANAGER', 'DGMS_INSPECTOR'
    contractor_id UUID NULL,                  -- Optional foreign key to external contractor agency
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2.2. `worker_credentials` (Eligibility for Edge Gate)
Stores statutory compliance dates for each worker. The Edge Gateway queries this table (or its local Redis cache) to authorize shaft descent.

```sql
CREATE TABLE worker_credentials (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    vtc_training_expiry DATE NOT NULL,         -- Vocational Training Centre certification
    pme_medical_expiry DATE NOT NULL,          -- Periodic Medical Examination clearance
    current_shift_start TIMESTAMPTZ NULL,      -- Overtime and continuous double-shift guard
    is_statutorily_eligible BOOLEAN GENERATED ALWAYS AS (
        vtc_training_expiry >= CURRENT_DATE AND 
        pme_medical_expiry >= CURRENT_DATE
    ) STORED
);
```

## 3. Spatial GIS & Location Module

### 3.1. `mine_locations` (PostGIS Geometries)
Stores topological and spatial definitions for both surface opencast workings and underground seams.

```sql
CREATE TABLE mine_locations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    location_name VARCHAR(255) NOT NULL,
    location_type VARCHAR(50) NOT NULL,         -- 'SURFACE_BENCH', 'UNDERGROUND_SEAM', 'SHAFT_COLLAR'
    rfid_beacon_id VARCHAR(128) UNIQUE,         -- For underground NFC/BLE tagging where satellite GPS is dead
    geom GEOMETRY(Geometry, 4326),              -- PostGIS Spatial Data (Points/Polygons)
    parent_location_id UUID REFERENCES mine_locations(id) -- Hierarchy (Seam -> District -> Pillar)
);
```

## 4. Hardware & Telemetry Module

### 4.1. `hardware_registry` (Hardware Ledger)
The master registry of all third-party physical devices integrated via Module 2.

```sql
CREATE TABLE hardware_registry (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    device_type VARCHAR(50) NOT NULL,           -- 'TURNSTILE', 'CCTV_CAMERA', 'GAS_SENSOR_CH4'
    location_id UUID REFERENCES mine_locations(id),
    ip_address VARCHAR(45),
    protocol VARCHAR(20),                       -- 'MODBUS', 'RTSP', 'MQTT'
    is_online BOOLEAN DEFAULT FALSE,
    last_heartbeat TIMESTAMPTZ
);
```

### 4.2. `sensor_telemetry` (TimescaleDB Hypertable)
High-throughput time-series table for environmental gas telemetry ($\text{CH}_4$, $\text{CO}$), airflow velocity, and hardware diagnostics.

```sql
CREATE TABLE sensor_telemetry (
    time TIMESTAMPTZ NOT NULL,
    hardware_id UUID REFERENCES hardware_registry(id),
    metric_type VARCHAR(50) NOT NULL,           -- 'CH4_PERCENT', 'CO_PPM', 'AIR_VELOCITY'
    reading_value DOUBLE PRECISION NOT NULL
);

-- Convert standard table to TimescaleDB hypertable partitioned by time (7-day chunks)
SELECT create_hypertable('sensor_telemetry', 'time', chunk_time_interval => INTERVAL '7 days');

-- Create a continuous aggregate (Materialized View) for Control Room Risk Dashboards
CREATE MATERIALIZED VIEW hourly_gas_averages
WITH (timescaledb.continuous) AS
SELECT time_bucket('1 hour', time) AS bucket,
       hardware_id,
       AVG(reading_value) AS avg_reading,
       MAX(reading_value) AS peak_reading
FROM sensor_telemetry
GROUP BY bucket, hardware_id;
```

## 5. Governance, Inspections & Audit Module

### 5.1. `compliance_violations` (The Remediation State Machine)
Tracks safety anomalies generated by the Edge Vision Gate (e.g., missing helmet, missing SCSR) or mobile field inspectors.

```sql
CREATE TABLE compliance_violations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    location_id UUID REFERENCES mine_locations(id),
    reporter_id UUID REFERENCES users(id) NULL, -- NULL if auto-generated by computer vision / IoT
    violation_type VARCHAR(100) NOT NULL,       -- e.g., 'MISSING_SCSR', 'ROOF_CONVERGENCE'
    severity VARCHAR(20) NOT NULL,              -- 'LOW', 'MEDIUM', 'HIGH', 'CRITICAL'
    status VARCHAR(50) DEFAULT 'DETECTED',      -- 'DETECTED' -> 'ACTION_TAKEN' -> 'CLOSED'
    deadline_sla TIMESTAMPTZ NOT NULL,          -- Drives Celery statutory escalation workers
    created_at TIMESTAMPTZ DEFAULT NOW(),
    resolved_at TIMESTAMPTZ NULL
);
```

### 5.2. `audit_ledger` (The Immutable Hash-Chain)
The blockchain-inspired, tamper-evident ledger recording all statutory approvals, shift sign-offs, and violation closures.

```sql
CREATE TABLE audit_ledger (
    seq_id BIGSERIAL PRIMARY KEY,
    timestamp TIMESTAMPTZ DEFAULT NOW(),
    actor_id UUID REFERENCES users(id),
    action_type VARCHAR(100) NOT NULL,          -- e.g., 'SHIFT_LOG_SIGNED', 'VIOLATION_CLOSED'
    payload JSONB NOT NULL,                     -- Point-in-time state snapshot
    previous_hash VARCHAR(64) NOT NULL,         -- SHA-256 hash of the PREVIOUS row (seq_id - 1)
    current_hash VARCHAR(64) NOT NULL           -- SHA-256(previous_hash || timestamp || actor_id || payload)
);
```

> [!NOTE]
> In the FastAPI application layer (`audit_service.py`), an atomic database insertion lock or sequential queue is enforced to ensure `previous_hash` is strictly read and linked sequentially to eliminate chain forks.

## 6. Document Digitization Module

### 6.1. `digitized_certificates` (OCR Extraction Targets)
Populated automatically by the PaddleOCR / LayoutLMv3 Celery workers when legacy paper records, medical fitness forms, and machinery certificates are uploaded.

```sql
CREATE TABLE digitized_certificates (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_type VARCHAR(100),                 -- 'DGMS_APPROVAL', 'FLPM_FITNESS', 'HEMM_MAINTENANCE'
    extracted_serial_no VARCHAR(100),
    issuing_authority VARCHAR(255),
    valid_from DATE,
    valid_until DATE,
    raw_text TEXT,                              -- Fallback for PostgreSQL full-text search (tsvector)
    s3_file_url VARCHAR(512),
    is_verified_by_human BOOLEAN DEFAULT FALSE
);
```
